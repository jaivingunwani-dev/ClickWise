================================================================================
                   BACKEND 500 ERROR - FIXES APPLIED
================================================================================

ISSUE: Backend threw 500 Internal Server Error during document analysis
CAUSE: Unhandled exceptions from missing API keys, mock credentials, etc.

================================================================================
                          3 FILES FIXED
================================================================================

1. backend/services/claude_client.py (NEW ERROR HANDLING)
   - Checks for empty/missing API key before initializing client
   - Returns RuntimeError instead of crashing
   - Router catches RuntimeError and returns 503 Service Unavailable

2. backend/services/caching/cache_service.py (GRACEFUL DEGRADATION)
   - Checks if Supabase credentials are real before initializing
   - Sets self.is_enabled = False for mock credentials
   - Cache operations silently skip if not enabled
   - Requests still succeed (cache is optional, not required)

3. backend/api/routes/documents.py (ERROR CLASSIFICATION)
   - Catches specific exception types with appropriate HTTP codes
   - RuntimeError (API not configured) → 503 Service Unavailable
   - ValueError (bad JSON response) → 400 Bad Request
   - Other exceptions → 500 Internal Server Error (only truly unexpected)

================================================================================
                         HOW ERRORS ARE HANDLED NOW
================================================================================

Missing API Key:
  1. User sends request to /api/v1/scan
  2. Router calls claude_client.analyze_document()
  3. Claude client checks: if not self.client: raise RuntimeError(...)
  4. Router catches RuntimeError
  5. Router raises HTTPException(503, "Configure API key")
  6. Response: 503 Service Unavailable with clear message
  7. Backend does NOT crash, returns meaningful error

Invalid Supabase Credentials:
  1. CacheService checks credentials on initialization
  2. self.is_enabled = False (cache disabled)
  3. User sends request to /api/v1/scan
  4. Router checks cache: cache_service.get_cached_analysis()
  5. Cache returns None (because disabled, not an error)
  6. Analysis proceeds normally with Claude API
  7. Router tries to store in cache (non-blocking operation)
  8. Cache gracefully skips storage if disabled
  9. Request succeeds despite missing Supabase
